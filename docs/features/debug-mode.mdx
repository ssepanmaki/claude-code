## Overview

The TUI (REPL) mode needs a real terminal, so it cannot be started for debugging through a VS Code launch configuration. Use **attach mode** to connect to a running Bun process.

## Steps

### 1. Start the inspect server in a terminal

```bash
bun run dev:inspect
```

It prints an address like `ws://localhost:8888/xxxxxxxx`.

### 2. Attach the debugger in VS Code

1. Set breakpoints in files under `src/`
2. Press F5 → choose **"Attach to Bun (TUI debug)"**

> **Note**: the WebSocket address in `dev:inspect` and in `launch.json` changes on every start, so both places must be updated together.

## How it works

The `dev:inspect` script actually runs `scripts/dev-debug.ts`:

```typescript
// scripts/dev-debug.ts
process.env.BUN_INSPECT = "localhost:8888/<token>"
await import("./dev")
```

Setting the `BUN_INSPECT` environment variable starts a Chrome DevTools Protocol compatible inspect server, and then the dev-mode entry is imported. The VS Code `bun` extension attaches by connecting to the printed address over WebSocket.

## JetBrains IDEs

In theory the JetBrains family (WebStorm / IntelliJ, etc.) can also attach to the Bun inspect server (Run → Attach to Process), but this has not been verified. If you get it working, contributions to this doc are welcome.
