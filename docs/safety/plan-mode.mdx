## The problem

You say "refactor this module" and the AI starts changing code immediately, but you haven't yet worked out how it plans to do it. By the time you realize halfway through that the direction is wrong, it is too late.

## The Plan Mode solution

Plan mode adds a "read-only phase" to the conversation, closed into a loop by two tools:

<Steps>
  <Step title="EnterPlanMode — enter plan mode">
    The AI decides on its own (or the user triggers it) that the task needs planning and calls `EnterPlanModeTool` (`packages/builtin-tools/src/tools/EnterPlanModeTool/EnterPlanModeTool.ts:36`). The tool requires **user approval** (`checkPermissions` returns `ask`).
  </Step>
  <Step title="Exploration — read-only toolset">
    The permission mode switches to `'plan'`, and the AI may only use tools whose `isReadOnly()` is true (Read, Grep, Glob, Agent, etc.). Write operations are denied automatically.
  </Step>
  <Step title="ExitPlanMode — submit the plan for approval">
    After exploring, the AI calls `ExitPlanModeV2Tool` (`packages/builtin-tools/src/tools/ExitPlanModeTool/ExitPlanModeV2Tool.ts:147`) to submit the plan file to the user for review. This is the second node that **requires user approval**.
  </Step>
  <Step title="Resume execution — full tool permissions">
    Once the user approves, the permission mode returns to what it was before, and the AI executes the plan.
  </Step>
</Steps>

## Automatic permission narrowing and restoration

### Entering: `prepareContextForPlanMode()`

The core logic of `EnterPlanModeTool.call()` (line 77):

```typescript
// 1. Record the transition (save the previous mode)
handlePlanModeTransition(currentMode, 'plan')

// 2. Switch the permission context to plan mode
context.setAppState(prev => ({
  ...prev,
  toolPermissionContext: applyPermissionUpdate(
    prepareContextForPlanMode(prev.toolPermissionContext),
    { type: 'setMode', mode: 'plan', destination: 'session' },
  ),
}))
```

What `prepareContextForPlanMode()` (`src/utils/permissions/permissionSetup.ts`) does:
- Creates a new `ToolPermissionContext` with `mode` set to `'plan'`
- In plan mode, a tool's `isReadOnly()` check becomes the only admission condition
- If the user's default mode is `'auto'`, it also activates the classifier's side effects

### Exiting: permission restoration + prompt-based permissions

The exit logic of `ExitPlanModeV2Tool` does two key things:

**1. Restores the permission mode**

It returns to the pre-entry mode through `handlePlanModeTransition()` and `applyPermissionUpdate()`.

**2. Injects prompt-based permissions**

This is the most elegant part of Plan Mode: the AI can declare, in the plan, the categories of commands it needs to run:

```typescript
// inputSchema of ExitPlanModeV2Tool
allowedPrompts: z.array(z.object({
  tool: z.enum(['Bash']),
  prompt: z.string().describe('Semantic description, e.g. "run tests"'),
})).optional()
```

If the AI declares `allowedPrompts: [{ tool: 'Bash', prompt: 'run tests' }]` when submitting the plan, then once the user approves, Bash commands of the "run tests" kind are allowed automatically, with no need to confirm them one by one.

## Plan file persistence

The plan is written to a file on disk (the path is determined by `getPlanFilePath()`), which is fundamentally different from the AI simply saying a few words and then starting to execute:

1. `normalizeToolInput` of `ExitPlanModeV2Tool` reads the plan from disk and injects it into `input.plan` and `input.planFilePath`
2. The plan file is **editable** by the user, who can modify the AI's plan before approving
3. The `planWasEdited` field marks whether the user changed the plan, which affects the later tool_result echo
4. `persistFileSnapshotIfRemote()` saves a file snapshot in remote scenarios

## Plan approval in the teammate scenario

In Agent Swarms mode (`isAgentSwarmsEnabled()`), plan approval has an extra collaboration flow:

```typescript
// If this is a Teammate
if (isTeammate()) {
  // Send the plan to the Team Leader's mailbox and wait for approval
  const requestId = generateRequestId()
  writeToMailbox(getTeamName(), {
    type: 'plan_approval_request',
    plan, requestId, ...
  })
  // Return awaitingLeaderApproval: true
  // After the Team Leader approves, the Teammate is notified via the mailbox
}
```

This means that in swarm mode the plan may be approved by the Team Leader rather than directly by the user.

## When to use plan mode

The prompt of `EnterPlanModeTool` (`packages/builtin-tools/src/tools/EnterPlanModeTool/prompt.ts`) defines two sets of trigger criteria: the external version is more eager (it encourages planning), and the internal version is more restrained (only when things are truly ambiguous):

| Scenario | External version | Internal version |
|------|---------|---------|
| Fix a typo | Skip | Skip |
| Add a delete button | **Enter** (touches several files) | **Skip** (clear path) |
| Refactor the authentication system | **Enter** | **Enter** (high-impact refactor) |
| "Start on X" | — | **Skip** (just start) |
| Architecture decision (Redis vs in-memory cache) | **Enter** | **Enter** (truly ambiguous) |

## Plan mode + the task system

Plan mode is usually paired with the task system:

1. In plan mode, the AI turns the implementation steps into a task list (`TodoWrite`)
2. The user approves the plan (including the task list)
3. After leaving plan mode, the AI works through the task list item by item
4. The user can track progress through the task list

## Full lifecycle

```
User: "Refactor this module"
  ↓
The AI decides planning is needed → calls EnterPlanModeTool
  ↓ User approval (Ask dialog)
handlePlanModeTransition(default, 'plan')  // save default
prepareContextForPlanMode()                // create a read-only context
  ↓
The AI explores the codebase with Read/Grep/Glob/Agent
  ↓ (possibly 10+ rounds of read-only tool calls)
The AI forms a plan → calls ExitPlanModeV2Tool({
  allowedPrompts: [
    { tool: 'Bash', prompt: 'run tests' },
    { tool: 'Bash', prompt: 'install dependencies' }
  ]
})
  ↓ User approves the plan (can edit the plan file)
Restore the permission mode → inject prompt-based permissions
  ↓
The AI executes the plan with all tools; commands like "run tests" are allowed automatically
```
