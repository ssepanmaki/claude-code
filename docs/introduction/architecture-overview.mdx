## Five-layer architecture

From top to bottom, Claude Code has five layers, each with a clear responsibility and boundary:

<Frame caption="The five layers of Claude Code">
  <img src="/docs/images/architecture-layers.png" alt="Claude Code five-layer architecture diagram" />
</Frame>

| Layer | Responsibility | Entry source | Keywords |
|------|------|---------|--------|
| **Interaction layer** | Terminal UI, user input, message display | `src/screens/REPL.tsx` | React/Ink, PromptInput |
| **Orchestration layer** | Multi-turn conversation, session persistence, cost tracking | `src/QueryEngine.ts` | QueryEngine, transcript |
| **Core loop layer** | One turn: send request → get response → run tools → loop | `src/query.ts` | Agentic Loop, State |
| **Tool layer** | The AI's "hands": read and write files, run commands | `src/tools.ts` → `src/Tool.ts` | Tool interface, MCP |
| **Communication layer** | Streaming communication with the Claude API | `src/services/api/claude.ts` | Streaming, Provider |

## Tracing one main data flow through the source

<Frame caption="The core data flow">
  <img src="/docs/images/data-flow.png" alt="Claude Code core data flow" />
</Frame>

The whole system can be condensed into one core data flow. The source path for each step:

### 1. User input → REPL

`src/screens/REPL.tsx` is a terminal UI component built on React/Ink. User input is handled by `processUserInput()` (`src/utils/processUserInput/processUserInput.ts`), which supports slash commands, file attachments, images and more.

### 2. QueryEngine orchestration

`src/QueryEngine.ts` is the middle layer between the REPL and `query()`. It manages:
- **Session state**: the message array, the tool permission context (`ToolPermissionContext`), and file history snapshots
- **Cost tracking**: `accumulateUsage()` / `getTotalCost()` accumulate token usage
- **Transcript persistence**: `recordTranscript()` serializes the conversation to disk and supports `--resume`
- **File history**: `fileHistoryMakeSnapshot()` creates a snapshot before modification and supports undo

Key method: `queryEngine.query()` builds `QueryParams` and calls the `query()` async generator.

### 3. The agentic loop (`src/query.ts`)

`query()` is an `AsyncGenerator`; each iteration of its `while(true)` loop contains:

```
① Context preprocessing pipeline:
   applyToolResultBudget → snipCompact → microcompact → contextCollapse → autocompact

② Streaming API call:
   deps.callModel() → AsyncGenerator<StreamEvent | Message>
   collects assistantMessages[], toolUseBlocks[]

③ Tool execution:
   StreamingToolExecutor (parallel) or runTools (serial)
   → toolResults[]

④ Terminate/continue decision:
   needsFollowUp ? continue : return { reason }
```

The full state machine is passed between iterations through the `State` type (`src/query.ts:207`), which has 10 fields (messages, autoCompactTracking, maxOutputTokensRecoveryCount, and so on).

### 4. The tool layer (`src/tools.ts` → `src/Tool.ts`)

`getAllBaseTools()` (`src/tools.ts:195`) assembles a list of 50+ tools, filtered by `filterToolsByDenyRules()` for permissions before being passed to the API.

Each tool implements the `Tool<Input, Output, Progress>` interface (`src/Tool.ts:368`). The core method chain:
```
validateInput() → canUseTool() (UI layer) → checkPermissions() → call() → ToolResult
```

### 5. The communication layer (`src/services/api/claude.ts`)

The API client supports 7 providers:
- **Anthropic Direct (firstParty)**: the default
- **AWS Bedrock**: `ANTHROPIC_BEDROCK_BASE_URL`
- **Google Vertex**: `ANTHROPIC_VERTEX_PROJECT_ID`
- **Foundry**: `ANTHROPIC_CODE_USE_FOUNDRY`
- **OpenAI**: compatibility layer
- **Gemini**: compatibility layer
- **Grok (xAI)**: compatibility layer

`deps.callModel()` starts a streaming request and returns a stream of `BetaRawMessageStreamEvent` events. It supports Prompt Cache (`cache_control`), thinking blocks, and multi-turn tool use.

## Four core design principles

<AccordionGroup>
  <Accordion title="Streaming-first">
    All API communication is streaming: `deps.callModel()` returns an AsyncGenerator, and the user sees the AI type its answer out word by word. StreamingToolExecutor starts running tools in parallel while the stream is still in progress, without waiting for it to end. On a model fallback, the collected assistantMessages are marked as tombstones and cleared, and the whole streaming request is retried.
  </Accordion>
  <Accordion title="Tool as Capability">
    Each tool is a structured `Tool<Input, Output, Progress>` type created through the `buildTool()` factory. `getTools()` assembles the list on every API call (no global cache) because `isEnabled()` may change with runtime state. MCP tools mark their origin through the `mcpInfo` field, which supports server-level blanket deny.
  </Accordion>
  <Accordion title="Permission as Boundary">
    Every tool call passes a double check of `validateInput() → checkPermissions()`. Permission rules come together from 5 sources (session → project → user → managed → default) and support matching by tool name, command pattern, path prefix and so on. Plan Mode switches to read-only mode through `prepareContextForPlanMode()` and restores automatically on exit.
  </Accordion>
  <Accordion title="Context as Memory">
    The System Prompt is assembled dynamically by `fetchSystemPromptParts()` and includes CLAUDE.md, git status, the date, and the MCP server list. Auto-compact evaluates the token threshold before each iteration and triggers compression when it is exceeded. The compressed summary replaces the original messages through `buildPostCompactMessages()`, and `taskBudgetRemaining` accumulates across the compaction boundary.
  </Accordion>
</AccordionGroup>

## Entry points and bootstrap

| Entry | File | Notes |
|------|------|------|
| CLI start | `src/entrypoints/cli.tsx` | Injects the `feature()` polyfill (always returns false) and the MACRO globals |
| Command definition | `src/main.tsx` | Commander.js parses arguments and initializes auth/analytics/policy |
| One-time initialization | `src/entrypoints/init.ts` | Telemetry config, trust dialog |
| Pipe mode | `src/main.tsx` `-p` flag | `echo "say hello" \| bun run dev -p` |
