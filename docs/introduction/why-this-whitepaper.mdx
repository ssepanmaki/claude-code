## What this whitepaper is

This is a **reverse-engineering analysis** of Anthropic's officially released **Claude Code CLI**.

The source was recovered by decompiling (reversing the single-file TypeScript bundle). The core feature modules are preserved, but there are many `unknown`/`never`/`{}` type errors. These do not affect execution on the Bun runtime, but they mean the analysis rests on runtime behavior plus the residual source structure, not on the original source.

**This is not:**
- Official documentation or a usage tutorial
- An API reference manual
- A sales pitch for Claude Code

**This is:**
- An architectural teardown of a production-grade agentic system
- The "why" behind each design decision
- Reusable engineering patterns: the agentic loop, tool abstraction, context engineering, defense in depth

## The most elegant design decisions found while reversing

### 1. The agentic loop heals itself

The core loop implemented in `src/query.ts` is not a simple "send request → receive response". It is a **self-healing state machine**:

- The API returns an error (rate limit, token limit) → automatic retry/downgrade
- A tool execution times out → backgrounding + a notification mechanism
- The conversation grows too long and triggers compaction → history is compressed and work continues seamlessly
- The user interrupts → a `UserInterruptionMessage` is generated so the AI understands what happened

This is not a pile of if-else; it lets the AI decide the next step from context, even when something unexpected happens.

### 2. Layered context engineering

An AI has no real "memory". Claude Code creates the illusion through careful layering:

| Layer | Mechanism | Persistence |
|----|------|--------|
| **System Prompt** | Project structure, git status, CLAUDE.md | Rebuilt every turn |
| **Conversation history** | Full User/Assistant/Tool messages | Within a session |
| **Compaction** | Automatically compresses an overlong conversation into a summary | Replaces the original messages after compression |
| **Memory files** | Notes persisted across sessions | Permanent (user-controlled) |
| **File History** | Snapshots of file modification timestamps | Within a session |

When `src/context.ts` assembles the System Prompt, the strategy is **unchanging content first, changing content last**. This exploits the API's caching: when the prefix is unchanged, cached tokens can be reused.

### 3. A dual-track permission model for tools

`packages/builtin-tools/src/tools/BashTool/shouldUseSandbox.ts` shows a clever two-layer security model:

- **Application layer**: permission rules decide "whether it may run" (allowlist/denylist/user confirmation)
- **OS layer**: the sandbox decides "what it can do while running" (filesystem/network/process isolation)

The two layers make different trust assumptions: the application layer trusts the user's configuration, while the OS layer trusts nothing. Even if the AI got around application-layer permissions (in theory impossible, but this is defense in depth), the OS-layer sandbox still limits the real damage.

### 4. A global feature flag switch

One line in `src/entrypoints/cli.tsx` determines the behavior of the whole system:

```typescript
const feature = (_name: string) => false;
```

Every `feature('FLAG_NAME')` call returns `false`, which means Anthropic's internal experimental features (COORDINATOR_MODE, KAIROS, PROACTIVE, and so on) are all disabled. In official builds these flags are injected at compile time through Bun's `bun:bundle`, and different user groups see different features.

This is a **progressive release architecture**: one codebase, with feature visibility controlled by feature flags, with no need to maintain multiple branches.

### 5. Tiered compaction

`src/services/compact/` implements three compaction strategies:

- **Micro-compact**: truncates the result when a single tool output is too long
- **Auto-compact**: compresses history automatically when the conversation's tokens approach the limit
- **Reactive-compact**: compresses in an emergency and retries when the API returns a token-limit error

This is not simply "cut the old messages". It uses the AI itself to summarize the earlier conversation and keep the semantics. After compression a `TombstoneMessage` is inserted to mark the boundary.
