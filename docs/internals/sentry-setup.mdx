## Overview

Claude Code can capture runtime exceptions through Sentry and report them to a Sentry instance you specify.

- **`SENTRY_DSN` set**: the Sentry SDK initializes automatically and captures unhandled exceptions and key errors
- **Not set**: every Sentry call is a no-op with zero overhead

## Environment variables

| Variable | Required | Description |
|---|---|---|
| `SENTRY_DSN` | Yes | Sentry project DSN, such as `https://xxx@o123456.ingest.sentry.io/789` |

This is the only variable needed; setting it enables Sentry.

## Usage

### Self-hosted Sentry

```bash
SENTRY_DSN=https://public_key@your-sentry.example.com/123 \
bun run dev
```

### Sentry Cloud (SaaS)

```bash
SENTRY_DSN=https://public_key@o123456.ingest.sentry.io/789 \
bun run dev
```

### Without Sentry (default)

```bash
bun run dev
# SENTRY_DSN is not set, so all sentry functions are no-ops
```

## Sentry server setup

### Steps

1. **Deploy a Sentry instance** (self-host with Docker, or use [sentry.io](https://sentry.io) Cloud)
2. **Create a Project** and choose the **Node.js** platform
3. Get the project's **DSN** (Settings → Projects → Client Keys → DSN)
4. Set the DSN as the `SENTRY_DSN` environment variable

## Details

### Error capture

- **Automatic**: `SentryErrorBoundary` wraps key React components and captures render errors
- **Manual**: `errorLogSink` reports to Sentry whenever it writes an error log
- **Graceful shutdown**: `closeSentry()` makes sure events are flushed when the process exits (2 s timeout)

### Security filtering

The `beforeSend` hook automatically strips these sensitive headers:

- `authorization`
- `x-api-key`
- `cookie`
- `set-cookie`

### Ignored error types

These error patterns are ignored and not reported:

| Error | Reason |
|---|---|
| `ECONNREFUSED` / `ECONNRESET` / `ENOTFOUND` / `ETIMEDOUT` | Network unreachable, not actionable |
| `AbortError` / `The user aborted a request` | Cancelled by the user |
| `CancelError` | Interactive cancel signal |

### Other settings

- **Sample rate**: `sampleRate: 1.0` (all error events are captured)
- **Breadcrumb limit**: `maxBreadcrumbs: 20` (keeps the payload small)
- **Performance transactions**: disabled (`beforeSendTransaction` returns `null`); only errors are reported

## API

| Function | Description |
|---|---|
| `initSentry()` | Initializes the SDK; called automatically in `src/entrypoints/init.ts` |
| `captureException(error, context?)` | Reports an exception manually, with optional extra context |
| `setTag(key, value)` | Sets a tag for grouping and filtering in the Sentry dashboard |
| `setUser({ id, email, username })` | Sets the user context for error attribution |
| `closeSentry(timeoutMs?)` | Flushes the queue and closes the client; call at process exit |
| `isSentryInitialized()` | Checks whether Sentry has been initialized |

## Implementation files

| File | Description |
|---|---|
| `src/utils/sentry.ts` | Core SDK initialization and wrapper |
| `src/components/SentryErrorBoundary.ts` | React Error Boundary component |
| `src/utils/errorLogSink.ts` | Error log sink, integrates `captureException` |
| `src/utils/gracefulShutdown.ts` | Graceful exit, calls `closeSentry()` |
| `src/entrypoints/init.ts` | Calls `initSentry()` at startup |
